# HotM 2026.5.10

**Release date:** 2026-05-11
**Type:** Patch — installer parity fix caught during mutsu (macOS) smoke test.

The Linux `.deb` postinst and the macOS `setup-macos.sh` enabled different Postgres extension sets. Both should match what Fortemi actually uses. This release aligns them.

## Install

### Linux (one command)

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash
```

### Linux (.deb direct)

```bash
sudo apt-get install ./HotM_2026.5.10_amd64.deb
```

### macOS

```bash
hdiutil attach HotM_2026.5.10_aarch64.dmg
cp -R "/Volumes/HotM/HotM.app" /Applications/
hdiutil detach "/Volumes/HotM"
xattr -cr /Applications/HotM.app
```

### Docker UI image

```bash
docker pull ghcr.io/fortemi/hotm-ui:2026.5.10
```

## What changed

### Fixed

**Linux postinst now enables the right Postgres extensions for Fortemi.**

Before: `vector, postgis, pg_trgm, pgcrypto`
After:  `vector, postgis, pg_trgm, unaccent`

The reasoning:
- **`pgcrypto` was unused.** Fortemi's migrations use `gen_random_uuid()` which has been a Postgres built-in since 13 (no extension needed) and `uuidv7()` which is a built-in since 18. Neither requires `pgcrypto`. The Linux postinst was enabling it for no reason.
- **`unaccent` is required.** Fortemi's `20260131000000_fts_unicode_normalization.sql` migration enables `unaccent` for accent-insensitive search ("café" matches "cafe"). It's a trusted extension that the `matric` role can create at migration time, so the absence didn't break installs — fortemi created it itself on first boot — but the install paths should be consistent.
- The macOS `setup-macos.sh` already enabled the right set. The fix is Linux-side only.

Postinst commentary now explains which extension each line covers and which trusted extensions Fortemi creates itself (`uuid-ossp` in the initial migration).

`docs/installation/desktop-linux.md` updated to match.

## Notes

- The `.deb` already declares `Depends: postgresql-contrib-18`, which ships both `pg_trgm` and `unaccent`. No apt resolution change.
- The new postinst is idempotent. Existing installs upgraded from v2026.5.9 or earlier retain `pgcrypto` (harmless leftover); re-running postinst just adds `unaccent` without removing `pgcrypto`. Operators who want a tidy state can `DROP EXTENSION pgcrypto` manually.
- No sidecar changes. Bundled Fortemi version stays v2026.5.6.
- No UI changes. `npm run typecheck` and `vitest --run` unchanged (1427 / 1427 passing).

## Compatibility

Drop-in upgrade from any v2026.5.x. No breaking changes.

Pairs with [HotM v2026.5.9](https://github.com/Fortemi/HotM/releases/tag/v2026.5.9) (inference response-shape fixes).
