# HotM 2026.5.6

**Release date:** 2026-05-10
**Type:** Patch — refreshed Fortemi sidecar + installer reinstall-path fixes.

Drop-in replacement. The desktop bundle re-pulls the current `Fortemi/fortemi` `sidecar-latest` at build time. Two `install.sh` defects that only manifested on reinstall over a partially-purged prior install are fixed; fresh-host installs are unchanged.

## Install

### Linux (one command)

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash
```

### Linux — Bring Your Own LLM

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash -s -- --no-ollama
```

### Linux (.deb direct)

```bash
sudo apt-get install ./HotM_2026.5.6_amd64.deb
```

### macOS

```bash
hdiutil attach HotM_2026.5.6_aarch64.dmg
cp -R "/Volumes/HotM/HotM.app" /Applications/
hdiutil detach "/Volumes/HotM"
xattr -cr /Applications/HotM.app
```

### Docker UI image

```bash
docker pull ghcr.io/fortemi/hotm-ui:2026.5.6
```

## What changed

### Changed

- **Bundled Fortemi sidecar** refreshed to current `sidecar-latest`. `desktop-release.yml` and `desktop-build-matrix.yml` curl from `https://git.integrolabs.net/Fortemi/fortemi/releases/download/sidecar-latest/` at build time — this release ships with whatever Fortemi's latest tagged sidecar build is at workflow run time.

### Fixed

- **PGDG GPG key now re-installed when the source list outlives the keyring** ([#200](https://git.integrolabs.net/Fortemi/HotM/issues/200)). On hosts that had been through `apt purge postgresql-common`, the keyring at `/etc/apt/keyrings/postgresql.gpg` got removed as a config file but the source list at `/etc/apt/sources.list.d/pgdg.list` survived. The previous `add_pgdg_repo()` short-circuited as soon as the source list was present, leaving the keyring absent. Reinstalls then warned `NO_PUBKEY 7FCC7D46ACCC4CF8` and silently fell back to cached apt index lists — the immediate install proceeded but every subsequent `apt-get update` failed signature verification until the user manually fixed it. The function now treats the source list and the keyring as independent prerequisites.

- **Ollama install survives orphan-group state from a prior install** ([#201](https://git.integrolabs.net/Fortemi/HotM/issues/201)). When `userdel ollama` had previously been refused with "group ollama not removed because it has other members", the upstream Ollama installer's `useradd` then failed (`group ollama exists`), exited non-zero, and `set -euo pipefail` aborted `install.sh` immediately after the upstream installer's misleading "Install complete" banner. The user was left with: no `ollama` user, no systemd unit, no model pulls, no final status banner — and no clear failure signal. `install.sh` now (a) pre-cleans an orphan `ollama` group before invoking the upstream installer, (b) wraps `curl | sh` so a non-zero upstream exit emits a warning instead of killing the script, and (c) checks for `/etc/systemd/system/ollama.service` after install and surfaces a remediation hint (`userdel ollama; groupdel ollama; re-run`) if it's still missing.

## Compatibility

Identical to v2026.5.5. No HotM contract changes, no API surface changes, no installer behavior changes for fresh-host installs. PostgreSQL 18 still required.

The bundled Fortemi sidecar refresh follows whatever `sidecar-latest` resolves to at build time — pin via `Fortemi/fortemi` directly if you need a specific Fortemi build.
