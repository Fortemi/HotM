# HotM v2026.4.0 Release Notes

**Release date:** 2026-04-23
**Channel:** stable

## Overview

HotM v2026.4.0 is the largest feature release since the initial SPA launch. Two major capabilities arrive together: an **embedded AI agent** that reasons over your knowledge base using Fortemi's local LLM stack, and a **native desktop application** that bundles the entire Fortemi backend as a sidecar — giving you a self-contained install on macOS and Linux with no separate database or API server required.

This release also ships a new inference settings panel, a rebuilt Regenerate AI workflow with real-time job progress, runtime API URL configuration for Docker, and a fully automated installer for unattended deployment.

---

## Highlights

### Embedded AI Agent

HotM now includes a conversational AI assistant that has direct access to your notes, attachments, and knowledge graph through Fortemi's local LLM stack.

The agent is designed for **local-first use**: no data leaves your machine. It runs against whatever model you have configured in Fortemi — Ollama (`qwen3:14b` by default) or a llama.cpp endpoint — and all tool calls go to your local Fortemi API.

**What it can do:**

| Tool | Description |
|------|-------------|
| Search notes | Full-text and semantic search across archives |
| Read notes | Retrieve note content and metadata |
| Browse concepts | Navigate NLP-extracted knowledge graph concepts |
| Access attachments | Reference and preview attached files in conversation |
| Cross-archive search | Federated queries spanning multiple archives |

**Architecture — XState v5 flow machine**

The agent runs an intent-driven state machine that opens with a conversational turn before offering tools, encouraging natural dialogue over reflexive tool use. Tool execution happens server-side in the agent-proxy service (AI SDK v6), keeping LLM credentials and tool logic off the browser.

```
User message
    ↓
Intent classification (conversational vs. tool-needed)
    ↓
Conversational response  ─── OR ───  Tool execution (server-side)
                                           ↓
                                    Inline result cards
                                    (thumbnails, media players, links)
```

**Session management**

Sessions persist across navigation and can be:
- Exported as JSON
- Saved as a note attachment (full context preserved for later review)
- Restored from any saved session note

**Agent proxy** is published as a Docker image alongside the UI image and is included in the standard `docker-compose.prod.yml` stack.

### Native Desktop App

HotM is now a self-contained desktop application. The entire Fortemi backend — API server, database, and file storage — runs as a bundled sidecar process. No separate installation required.

**How it works:**

```
┌─────────────────────────────────────────────┐
│  HotM Desktop (Tauri)                        │
│                                              │
│  ┌──────────────────────────────────────┐    │
│  │  WebView (React SPA)                 │    │
│  │  window.__HOTM_HOST__ (host adapter) │    │
│  └──────────────┬───────────────────────┘    │
│                 │ hotm_fetch / hotm_sse       │
│  ┌──────────────▼───────────────────────┐    │
│  │  Tauri host process (Rust/reqwest)   │    │
│  └──────────────┬───────────────────────┘    │
│                 │ HTTP loopback              │
│  ┌──────────────▼───────────────────────┐    │
│  │  matric-api sidecar                  │    │
│  │  (Fortemi — free port, auto-spawned) │    │
│  └──────────────┬───────────────────────┘    │
└─────────────────┼────────────────────────────┘
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
  PostgreSQL    Ollama    File storage
```

The host-proxy pattern routes all HTTP requests and SSE streams through Rust's `reqwest` backend, bypassing WebKit2GTK's network restrictions. The `sidecar:ready` event fires when the backend is accepting connections, eliminating race conditions on startup.

**Desktop-specific features in this release:**

| Feature | Details |
|---------|---------|
| Global shortcut | `Cmd+Alt+H` (macOS) / `Ctrl+Alt+H` (Linux) — toggle window from anywhere |
| `--minimized` flag | Launch silently in tray; useful for autostart-on-login |
| Close-to-tray | Window close hides the app; Quit stops the sidecar |
| Config persistence | `get_app_config`/`save_app_config` — API URL and database DSN survive restarts |
| PlantUML rendering | Built-in diagram rendering via local PlantUML server (optional) |

**Distribution packages** are built automatically on every push to `main` via the new CI build matrix:
- macOS: `.dmg` (Apple Silicon, built on mutsu Mac runner)
- Linux: `.AppImage` and `.deb`

### `__HOTM_HOST__` Embedding Adapter

HotM can now be embedded in third-party shells (browser extensions, Electron wrappers, custom desktop apps) via the `__HOTM_HOST__` adapter protocol.

A host injects `window.__HOTM_HOST__` before the SPA loads:

```javascript
window.__HOTM_HOST__ = {
  network: {
    fetch: (url, options) => customFetch(url, options),
    sse:   (url, options) => customSSE(url, options),
  }
};
```

All API calls and SSE connections route through the provided overrides. Standalone Tauri mode injects its own adapter automatically. Web/Docker mode uses native `fetch`/`EventSource`.

### Inference Settings

A new **Admin → Inference** panel gives full control over LLM configuration:

- **Provider selection**: Ollama and llama.cpp supported; OpenAI/OpenRouter via the existing API
- **Model configuration**: generation model, embedding model, context window
- **Connection test**: live health check with per-provider status indicator in the nav bar
- **Granular regeneration**: choose model, revision mode, context filter, processing steps, and specific job types when triggering AI reprocessing

The regeneration workflow has been rebuilt with a progress panel showing real-time job status as Fortemi processes each pipeline stage.

## Breaking Changes

None. HotM v2026.4.0 is backwards-compatible with Fortemi API v1.

The agent proxy is a new optional service. Existing Docker deployments work unchanged; add the agent proxy container to access the AI agent feature.

---

## Known Limitations

- **DOCKED_BAR player state** — defined in the media player state machine but deferred; falls back to MINI
- **Native Picture-in-Picture** — fullscreen via container is the current path; element-level `requestPictureInPicture()` not yet integrated
- **Agent on mobile** — agent panel not optimized for viewports < 640px
- **PlantUML** — requires a separately running PlantUML server on `localhost:8080`; diagrams degrade gracefully to source text when unavailable

## Installation

### Desktop (recommended)

Download from the [releases page](https://git.integrolabs.net/Fortemi/HotM/releases):

- **macOS**: `HotM_2026.4.0_aarch64.dmg`
- **Linux (AppImage)**: `hot-m_2026.4.0_amd64.AppImage`
- **Linux (deb)**: `hotm_2026.4.0_amd64.deb`

The sidecar requires PostgreSQL accessible at the configured `database_url` (defaults to `postgres://matric:matric@localhost/matric`). See the [operator guide](../operations/operator-guide.md) for full setup.

### Docker

```bash
git clone git@git.integrolabs.net:Fortemi/HotM.git
cd HotM
docker compose -f docker-compose.prod.yml up -d
```

The stack includes the UI, nginx reverse proxy, and agent proxy. Set `VITE_API_BASE_URL` in your environment to point at your Fortemi API instance.

### Development

```bash
git clone git@git.integrolabs.net:Fortemi/HotM.git
cd HotM/ui
npm install
npm run dev
```

For Tauri desktop development:

```bash
cd HotM/ui
npm run tauri:dev
```

### Environment Variables

```bash
VITE_API_BASE_URL=http://localhost:3000   # Fortemi API base URL
VITE_DISABLE_WEBSOCKET=true              # optional: fall back to SSE only
VITE_SENTRY_DSN=https://...              # optional: Sentry error tracking
```
