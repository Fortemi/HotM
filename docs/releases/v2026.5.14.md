# HotM 2026.5.14

**Release date:** 2026-05-26
**Type:** Feature - latest Fortemi API surface integration and operator controls.

This release brings HotM's UI and local API compatibility snapshot forward for the latest Fortemi sidecar surfaces reviewed from the local Fortemi v2026.5.13 source checkout. The biggest user-visible change is a new set of Admin controls for API capability inspection, custom document types, and outbound webhooks.

## Install

### Linux (one command)

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash
```

### Linux (.deb direct)

```bash
sudo apt-get install ./HotM_2026.5.14_amd64.deb
```

### macOS

```bash
hdiutil attach HotM_2026.5.14_aarch64.dmg
cp -R "/Volumes/HotM/HotM.app" /Applications/
hdiutil detach "/Volumes/HotM"
xattr -cr /Applications/HotM.app
```

### Docker UI image

```bash
docker pull ghcr.io/fortemi/hotm-ui:2026.5.14
```

## What changed

### Admin API Surface

Admin now has an **API Surface** tab that shows the currently configured sidecar endpoint, health status, Fortemi version, database and Ollama state, realtime counters, advertised capabilities, degraded-mode guidance, and HotM's wired feature coverage. This gives operators a single place to confirm whether the latest Fortemi features are available without opening developer tools.

### Document Types

Admin now has a **Document Types** tab for listing Fortemi document types, creating custom types, and deleting only custom types. System document types are displayed but protected from destructive actions.

### Webhooks

Admin now has a **Webhooks** tab for registering outbound webhook targets, selecting lifecycle events, configuring retry count and optional secret, testing delivery, and deleting registrations.

### Create-note and processing contract alignment

The local OpenAPI compatibility snapshot now documents the UI-used create-note additions: explicit `title`, revision mode, document type selection, context filters, and processing options. The Quick Note sidebar remains a fast capture path, while advanced note creation continues through Quick Capture as the canonical workflow.

### Reprocess and backup import

The compatibility snapshot and tests cover queued bulk reprocess and backup import with deferred inference. This keeps large archive import workflows explicit and avoids hiding semantic backfill behind a blocking UI path.

### Planning and release evidence

## Compatibility

No breaking changes to existing HotM workflows. New Admin screens are additive, and existing API client behavior remains compatible with older sidecar responses where fields are absent.

Latest-source confirmation used the local Fortemi v2026.5.13 source checkout. No generated upstream Fortemi OpenAPI artifact was present there during the review, so canonical upstream OpenAPI diffing is documented as a follow-up control.
