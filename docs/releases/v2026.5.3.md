# HotM 2026.5.3

**Release date:** 2026-05-08
**Type:** Patch — cleanup release on top of v2026.5.2's installer rework.

Drop-in replacement. Same install path as v2026.5.2; this release fixes one re-install edge case and finishes the cleanup of the deprecated `setup-linux.sh`.

## Install

### Linux (one command)

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash
```

The installer is idempotent — running it on a host already at 2026.5.2 will detect the prior install, skip the .deb step, install the latest if not present, and apply the ollama dir fix on the next service start. See [`docs/quick-start.md`](../quick-start.md) for the user-friendly version or [`docs/installation/desktop-linux.md`](../installation/desktop-linux.md) for the full breakdown.

### Linux (.deb direct)

```bash
sudo apt-get install ./HotM_2026.5.3_amd64.deb
```

### macOS

```bash
hdiutil attach HotM_2026.5.3_aarch64.dmg
cp -R "/Volumes/HotM/HotM.app" /Applications/
hdiutil detach "/Volumes/HotM"
xattr -cr /Applications/HotM.app
```

### Docker UI image

```bash
docker pull ghcr.io/fortemi/hotm-ui:2026.5.3
```

## What changed

### Fixed

- **Ollama service failed to start on dirty re-installs.** The upstream Ollama installer's idempotency logic skips data-directory creation when the `ollama` system user already exists from a prior install. On boxes where `/usr/share/ollama` was wiped manually but the user persisted, `ollama.service` then crash-looped with `could not create directory mkdir /usr/share/ollama: permission denied`. `install.sh` now defensively `install -d -o ollama:ollama /usr/share/ollama` after the upstream curl-pipe-bash. No-op on a true fresh install.

### Removed

- **`scripts/setup-linux.sh`** — fully superseded by `scripts/install.sh` and the `.deb` postinst hook in v2026.5.2. Deprecation banner shipped in v2026.5.2; deleted in this release.

### Documentation

- **`docs/quick-start.md`** rewritten around the single-command install. Stale references to `setup-linux.sh` and pinned version strings (`HotM_2026.2.0_*`) replaced with the current `install.sh` one-liner and links to the `releases/latest` page.

## Compatibility

Identical to v2026.5.2. PostgreSQL 18 still required (uuidv7 dependency in matric-api migrations).

## Verification

Installer logic verified by replaying the dirty-reinstall scenario that produced the original ollama startup failure. After this release the path completes clean: ollama systemd unit reaches `active` on first boot.

Pairs with [v2026.5.2](https://github.com/Fortemi/HotM/releases/tag/v2026.5.2) (the installer rework release).
