# HotM 2026.9.4

HotM 2026.9.4 corrects authenticated realtime session binding. The UI derives a
tenant hint from the current bearer to narrow rendered events and clears stale
tenant context when credentials are replaced. The server still verifies the
token and authorizes access. A bearer without a tenant hint receives the real
server rejection; even a successful stream cannot dispatch events without the
tenant filter.

The release adds a host-independent live browser qualification runner covering
real authorization failures, two-tenant note and realtime isolation, natural
token expiry, replacement credentials with reload, and exact fixture cleanup.
It performs compatibility preflight before requesting credentials and records
incremental results. See [hosted realtime qualification](../testing/hosted-realtime-qualification.md)
for the command, deployment requirements, credential custody, and test boundaries.
The agent-proxy test lockfile also includes the patched Vitest mocker dependency.

Hosted admission remains Fortemi Auth `v2026.9.0`, claim contract `1.1.0`, profile
`rust-node-jwt-v1`. The packaged desktop sidecar pin is unchanged. Configure a
browser deployment's API base with `/api/v1`; replacement bearer credentials
require a page reload to recreate the transport. This is bearer-session
qualification, not an interactive OIDC sign-in feature. Broader hosted route
coverage, Windows qualification, and suite-wide portability remain outside this
release's claims.
