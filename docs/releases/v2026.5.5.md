# HotM 2026.5.5

**Release date:** 2026-05-10
**Type:** Patch — refreshed Fortemi sidecar + onboarding-docs cleanup.

Drop-in replacement. The desktop bundle re-pulls the current `Fortemi/fortemi` `sidecar-latest` at build time, so this release ships with the latest backend without any contract or installer-behavior changes. Onboarding docs and the installer script clarify the BYO-LLM path so users with existing llama.cpp / vLLM / OpenAI-compatible endpoints can skip the bundled Ollama install.

## Install

### Linux (one command)

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash
```

The installer is idempotent. Hosts already on 2026.5.4 will pick up the newer `.deb` on the next run.

### Linux — Bring Your Own LLM

If you already run llama.cpp, vLLM, or any OpenAI-compatible endpoint, skip the bundled Ollama install. Fortemi is configurable for any inference backend.

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash -s -- --no-ollama
```

The installer now prints the relevant Fortemi env vars (`MATRIC_INFERENCE_DEFAULT`, `LLAMACPP_BASE_URL`, etc.) at the end of a `--no-ollama` run. See [docs/quick-start.md](https://git.integrolabs.net/Fortemi/HotM/src/branch/main/docs/quick-start.md#bring-your-own-llm) for the full BYO matrix.

### Linux (.deb direct)

```bash
sudo apt-get install ./HotM_2026.5.5_amd64.deb
```

### macOS

```bash
hdiutil attach HotM_2026.5.5_aarch64.dmg
cp -R "/Volumes/HotM/HotM.app" /Applications/
hdiutil detach "/Volumes/HotM"
xattr -cr /Applications/HotM.app
```

### Docker UI image

```bash
docker pull ghcr.io/fortemi/hotm-ui:2026.5.5
```

## What changed

### Changed

- **Bundled Fortemi sidecar** refreshed to current `Fortemi/fortemi` `sidecar-latest`. Both `desktop-release.yml` and `desktop-build-matrix.yml` curl the sidecar at build time from `https://git.integrolabs.net/Fortemi/fortemi/releases/download/sidecar-latest/`, so this release ships with whatever Fortemi's latest tagged sidecar build is at the moment the workflow runs. No HotM-side contract change.

### Documentation

- **Three-path quick-start decision tree** ([#198](https://git.integrolabs.net/Fortemi/HotM/issues/198)). `docs/quick-start.md` now opens with a table distinguishing the Desktop bundle (~10 GB, includes Ollama), Docker UI + external Fortemi (~200 MB), and Bring Your Own LLM paths so users land on the install path that matches their setup. The full *Bring Your Own LLM* section walks through the `--no-ollama` install and the Fortemi env vars to switch backends.

- **`scripts/install.sh` advertises `--no-ollama`** ([#198](https://git.integrolabs.net/Fortemi/HotM/issues/198)). Usage block promotes the BYO-LLM use case to first-class. On `--no-ollama` runs, the installer now prints concrete Fortemi config hints (`MATRIC_INFERENCE_DEFAULT=llamacpp`, `LLAMACPP_BASE_URL=http://localhost:8080/v1`, link to the Fortemi configuration docs) instead of the previous generic "degraded mode" warning.

- **`.env.example` separation** ([#198](https://git.integrolabs.net/Fortemi/HotM/issues/198)). Split into a UI section (`VITE_API_BASE_URL` only — actually read by the React app) and a Fortemi-backend section with an explicit "NOT read by HotM UI" notice and a link to Fortemi's configuration docs. Prevents users from copying the root `.env` and concluding HotM controls inference.

- **`docker-compose.prod.yml` header narrative** ([#198](https://git.integrolabs.net/Fortemi/HotM/issues/198)). New comment block clarifies the stack is stateless UI + agent-proxy only — no Fortemi, no PostgreSQL, no LLM. Calls out that `OLLAMA_URL` is consumed by the agent-proxy for direct UI-side completions and is independent of whatever inference backend Fortemi itself uses.

### Fixed

- **Flaky `EmbeddingSetManager` dialog-close tests** ([#199](https://git.integrolabs.net/Fortemi/HotM/issues/199)). Three Cancel-close tests intermittently timed out at the vitest 5000 ms default under the full `act_runner` quality-gate parallel load. Root cause: Radix Dialog's `Presence` waits for `animationend` events that jsdom does not fire reliably under heavy event-loop contention — load-induced timeout, not a test code race (the same suite passes 50/50 in isolation in ~11 s). Per-test timeout bumped to 15 s on the three affected tests with an inline comment linking this issue. Verified stable across 5 consecutive quality-gate runs.

## Compatibility

Identical to v2026.5.4. Host-adapter contract unchanged, API surface unchanged, installer behavior unchanged. PostgreSQL 18 still required (uuidv7 dependency in matric-api migrations).

The bundled Fortemi sidecar refresh follows whatever `sidecar-latest` resolves to at build time — if you are validating against a specific Fortemi build, pin via `Fortemi/fortemi` directly rather than via this release.
