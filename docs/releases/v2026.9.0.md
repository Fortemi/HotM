## #304 realtime/auth status

The client now separates reachable-but-unauthorized realtime sessions from transport outages. SSE `401` and `403` responses become terminal auth-required status instead of generic reconnecting. Legacy WebSocket `410` is treated as expected legacy incompatibility for non-anonymous-local mode. Native auth probes are deduplicated and guarded by connection generation so a delayed probe cannot terminate a newer connection. Successful reauthentication resumes realtime delivery.

## #173 installed-client reprocess

The installed immutable UI at `http://127.0.0.1:4180` served runtime config pointing at `http://localhost:4180/api/v1`. Browser-originated Backup → Reprocess requests crossed loopback host spellings, stayed queued in the UI, and did not produce the required title/revision behavior.

The fix normalizes only same-protocol, same-port loopback API base URLs to the browser page origin. A page loaded from `127.0.0.1` with runtime config set to `localhost` now calls `127.0.0.1` for API, compatibility, and realtime paths. Split-port development and non-loopback deployments are preserved.

Delivered evidence:

- PR #308 delivered by direct fast-forward to `de1ff24dc69c4f44530d201c8ab6c977fe3369fa`.
- Current-head CI for `de1ff24dc69c4f44530d201c8ab6c977fe3369fa` passed: sdlc-gates `54424`, tauri-build `54425`, and ui-ci `54426`.
- Direct backend control on a new synthetic media fixture returned HTTP 200, queued forced `title_generation` and `ai_revision`, and changed the AI revision.
- Branch browser proof served this branch from `http://127.0.0.1:15573` with runtime config deliberately set to `http://localhost:15573/api/v1`; the browser sent `POST http://127.0.0.1:15573/api/v1/notes/reprocess`, received HTTP 200, queued and completed `title_generation` and `ai_revision`, changed the AI revision, and cleaned the synthetic fixture.

The branch browser proof does not claim visible installed title change. The proof records title-generation job completion and revision changed `true`; title behavior and revision behavior must remain separate in the installed-artifact qualification receipt.
