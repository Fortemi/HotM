# HotM 2026.5.8

**Release date:** 2026-05-11
**Type:** Feature — closes [epic #202](https://git.integrolabs.net/Fortemi/HotM/issues/202) (UI consumption of Fortemi runtime inference-config surface).

Six child issues land together. The InferenceSettings form gains a routing card, a fourth provider (OpenRouter), four save modes, capability badges, and an optional `scope` prop that powers per-archive overrides via the X-Fortemi-Memory header. AdminPanel gains an Audit Log tab. ArchiveManager gains an Inference action per archive.

## What changed

### Inference Settings — major extension

**OpenRouter card** ([#204](https://git.integrolabs.net/Fortemi/HotM/issues/204))

A fourth provider joins Ollama / OpenAI / llama.cpp. OpenRouter is generation-only — the card has no embedding model field. Two extra fields surface the platform's required headers: `http_referer` and `app_name` (X-Title). Capability badges (Generation / Embedding / Vision) now render on every provider card sourced from a new `PROVIDER_PROFILES` catalog that mirrors `Fortemi/crates/matric-inference/src/provider_profiles.rs`.

**Routing card** ([#205](https://git.integrolabs.net/Fortemi/HotM/issues/205))

New panel above the provider cards. Default backend dropdown (all four providers) plus a "Route embeddings independently" toggle + dropdown filtered to embedding-capable providers only (Ollama, OpenAI). Tri-state semantics on `embedding_backend` (omit / clear / set) match the Fortemi `Option<Option<String>>` field. Active routing summary line — "Generation: openrouter — Embeddings: ollama" — updates live.

**Save modes** ([#206](https://git.integrolabs.net/Fortemi/HotM/issues/206))

Save is now a split-button. The primary button still performs the plain hot-swap; the chevron dropdown exposes three additional modes:

- **Validate before save** — `?validate=true`. Probes each touched provider's endpoint before persisting. Fails with a reason if any are unreachable.
- **Atomic save** — `?atomic=true`. Probes ALL touched providers before commit. Returns 503 with per-provider failure detail if any probe fails. The live registry is left unchanged on failure.
- **Preview changes (dry-run)** — `?dry_run=true`. Opens a side-by-side JSON diff modal showing the current effective config vs the would-be config. Does NOT persist or emit an SSE event.

**Per-archive overrides** ([#208](https://git.integrolabs.net/Fortemi/HotM/issues/208))

`InferenceSettings` accepts an optional `scope` prop. Composition over inheritance — a single component serves both global and archive scope. When `scope` is set, every API call sends the `X-Fortemi-Memory` header and reads merge the archive override over the global config.

`ArchiveManager` gains an **Inference** action per archive (Sparkles icon) that opens a dialog rendering `<ArchiveInferenceSettings archive={name} />`. An orange deferred-hot-swap banner appears above the form when scope is set, calling out that overrides persist but are not yet routed in the live runtime — pending a Fortemi-side follow-up.

### SSE subscriptions ([#203](https://git.integrolabs.net/Fortemi/HotM/issues/203))

`RealtimeEventType` extended with `InferenceConfigChanged` and `InferenceAvailabilityChanged`. The dot-notation map adds `inference.config.changed` and `inference.availability.changed`. The default SSE subscriber list now includes both.

**`InferenceSettings`** subscribes and reacts based on form state:
- Form clean → silent refetch + toast naming the changed fields
- Form dirty → non-blocking amber banner offering Refresh (discards edits) or Dismiss (keeps edits)
- Sentinels handled: `__reset__` (global reset) → full refetch + reset toast; `__reset_archive__` → filtered by scope

**`InferenceStatusIndicator`** subscribes to availability changes — flips the dot color from the event's `reachable` flag without a full config refetch.

### Audit Log tab in AdminPanel ([#207](https://git.integrolabs.net/Fortemi/HotM/issues/207))

New `Audit Log` tab next to Inference in AdminPanel. The viewer renders entries from `GET /api/v1/inference/config/audit` (Fortemi #656) in a paginated table:

- Action-colored badges: `set` (blue), `reset` (amber), `set_archive` (teal), `reset_archive` (orange)
- Expandable rows showing the `before_json` / `after_json` diff in a side-by-side layout
- Filters: actor (text input), action (dropdown), limit (20 / 50 / 100 / 200)
- Auto-refreshes on `InferenceConfigChanged` events
- API keys remain redacted server-side — never reconstructed client-side

### API client changes

```ts
// Backward-compatible — all new args are optional.
api.inference.getConfig(scope?: { archive: string }): Promise<InferenceConfig>
api.inference.updateConfig(
  update: InferenceConfigUpdate,
  options?: { validate?: boolean; atomic?: boolean; dryRun?: boolean },
  scope?: { archive: string },
): Promise<InferenceConfig>
api.inference.resetConfig(scope?: { archive: string }): Promise<void>
api.inference.getAuditLog(query?: {
  limit?: number;
  changedBy?: string;
  action?: 'set' | 'reset' | 'set_archive' | 'reset_archive';
}): Promise<{ entries: AuditEntry[] }>
```

`updateConfigValidated` is marked `@deprecated`. Existing callers continue to work; new code should pass `{ validate: true }` to `updateConfig` instead.

`InferenceConfig.embedding_backend` is the new optional `string | null` field exposing the routing override. `InferenceConfigUpdate.embedding_backend` is tri-state: omit the key to leave unchanged, set `null` to clear, set a string to route.

## Compatibility

No breaking changes to existing API or UI surfaces. All new component props and API arguments are optional. The dependent Fortemi version is **v2026.5.6** (the bundled sidecar already includes the inference-config epic on the API side).

## Known follow-ups (filed under [#202](https://git.integrolabs.net/Fortemi/HotM/issues/202))

- Fortemi-side enhancement to add `archive_name` to the `InferenceConfigChanged` event payload so the per-archive UI can filter event handling to the open scope. Today the filter falls back to no-op when `archive_name` is absent.
- Fortemi-side live runtime per-archive routing (the gap acknowledged in the #655 PR description — overrides persist but don't hot-swap to the live registry).
