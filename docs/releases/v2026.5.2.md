# HotM 2026.5.2

**Release date:** 2026-05-08
**Type:** Feature — installer rework. Single-command Linux install, .deb postinst, Postgres 18 standardization.

This release replaces the previous fragmented Linux install path (separate `setup-linux.sh` + manual `dpkg -i`) with a single bootstrap script and a self-contained `.deb` whose postinst seeds the `matric` database on `apt`'s behalf. It also pins HotM to PostgreSQL 18 — the [matric-api migrations](https://git.integrolabs.net/Fortemi/fortemi/issues/635) call `uuidv7()`, a PG 18 built-in.

## Install

### Linux (one command)

```bash
curl -fsSL https://git.integrolabs.net/Fortemi/HotM/raw/branch/main/scripts/install.sh | bash
```

The script:

1. Adds the [PGDG](https://wiki.postgresql.org/wiki/Apt) apt repo for your distro (verifies the codename is published before writing the source)
2. Downloads + checksum-verifies `HotM_2026.5.2_amd64.deb`
3. Runs `apt install` — pulls `postgresql-18`, `postgresql-contrib-18`, `postgresql-18-pgvector`, `postgresql-18-postgis-3`, `libwebkit2gtk-4.1-0` automatically via the .deb's `Depends:`/`Recommends:`
4. Postinst seeds the `matric` role + database, enables `vector`, `postgis`, `pg_trgm`, `pgcrypto` extensions, self-checks `uuidv7()` resolves
5. Installs the official Ollama daemon and pulls `nomic-embed-text` + `qwen3.5:9b` in the background (~5-15 min)
6. Reports installed status and next steps

Idempotent — re-running is safe and skips anything already in place.

Audit before piping:
```bash
curl -fsSL https://git.integrolabs.net/Fortemi/HotM/raw/branch/main/scripts/install.sh | less
```

Available flags: `--version`, `--no-ollama`, `--skip-models`, `--embed-model`, `--gen-model`, `--local-deb`. See [`docs/installation/desktop-linux.md`](../installation/desktop-linux.md).

### Linux (manual / advanced)

## What changed

### Added

- **`scripts/install.sh`** — one-command Linux bootstrap. Resolves the latest release via the Gitea API with a tag-pattern filter (`^v[0-9]+\.[0-9]+\.[0-9]+$`); replaces the previous fragile atom-feed regex. SHA256SUMS verification rewritten in `awk` to handle both bare-filename and full-path entries (and to be `pipefail`-safe).
- **`.deb` postinst hook** — creates the `matric` role + database, enables the four required extensions, self-checks `uuidv7()` before declaring success.
- **PGDG apt repo bootstrap** in `install.sh`. Verifies the host's codename has a published PGDG release (`questing-pgdg`, `noble-pgdg`, `bookworm-pgdg`, etc.) before writing the source — fails fast on unsupported distros.

### Changed

- **PostgreSQL 18 is now the supported runtime.** The `.deb` declares `Depends: postgresql-18, postgresql-contrib-18` (was `postgresql (>= 14)`) and `Recommends: postgresql-18-pgvector, postgresql-18-postgis-3`. Required because the matric-api migration `20260215000000` calls `uuidv7()`, a PG 18 built-in (RFC 9562) that doesn't exist on PG 13–17.
- **`docs/installation/desktop-linux.md`** rewritten around the single-command install. Documents what `install.sh` does step-by-step. Manual-install path retained for advanced users; troubleshooting adds a `function uuidv7() does not exist` entry pointing at PG 18 / PGDG.
- **`scripts/setup-linux.sh`** marked DEPRECATED — superseded by `install.sh` + the `.deb` postinst. (Deleted in v2026.5.3.)

### Removed

- **`setup_ollama.sh`** at repo root. Duplicated the Ollama install logic and used a different model name (`gpt-oss:20b`) than the rest of the project. Models are now standardized in one place: `nomic-embed-text` + `qwen3.5:9b`.

## Notes

- **The dpkg package name is `hot-m`** (Tauri's bundler kebab-cases the `productName` "HotM" when generating the deb's control file). Use `apt remove hot-m` / `dpkg-reconfigure hot-m`. The user-facing app and binaries (`/usr/bin/hotm`, `/usr/bin/hotm-matric-api`) are still named `hotm`.
- **Verified end-to-end** on a fresh Ubuntu 25.10 host (`questing-pgdg`): apt resolves `postgresql-18 18.3-1.pgdg25.10+1`, `postgresql-18-pgvector 0.8.2`, `postgresql-18-postgis-3 3.6.3`; postinst seeds the matric DB cleanly; matric-api migrations complete using native PG 18 `uuidv7()`.
- **Matric-api portability** — see [Fortemi/fortemi#635](https://git.integrolabs.net/Fortemi/fortemi/issues/635) for the parallel issue making the `uuidv7()`-using migration portable upstream so non-HotM consumers of matric-api don't need PG 18.

## Compatibility

| Component | Version |
|---|---|
| Fortemi (matric-api) | 2026.5.0+ (unchanged from HotM v2026.5.1) |
| PostgreSQL | **18.x required** (regression from prior versions; uuidv7 dependency) |
| Host adapter contract | v1, canonical `__HOTM_HOST__` symbol only |

## Verification

End-to-end install validated on a clean Ubuntu 25.10 host with NVIDIA GPU. `dpkg -l hot-m`, `psql -U postgres -tAc "SHOW server_version"` (18.3), `\dx` showing `vector`, `postgis`, `pg_trgm`, `pgcrypto`, `SELECT uuidv7()` returning a valid v7 UUID, `systemctl is-active ollama` (active), models pulled.
