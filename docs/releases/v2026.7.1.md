# HotM 2026.7.1

**Release date:** 2026-07-29

**Type:** Signed consumer-conformance and Mutsu reliability release

**Portable-data scope:** exact `2.0.0/full-v1` at receipt-bound revisions

This release advances HotM to the latest validated Fortemi server and
React/core consumer chain, hardens native macOS automation after the Mutsu
host crash, and keeps HotM in its intended role as an API consumer. Fortemi
remains the schema and server-policy authority.

  pinned by size and SHA-256 in `release/sidecar-provenance.json`.

The event and OpenAPI consumer receipts are regenerated from the exact
sidecar producer commit. The Knowledge Shard verifier continues to name and
test its separate `core-v1` and `full-v1` authorities rather than treating
route presence or a vendored fixture as portability evidence.

## Mutsu recovery

The host was cleaned of abandoned dependency trees and oversized virtual
machine disks, rebooted, and revalidated for native Linux arm64 and macOS
arm64 work. Shared SSH authorization is available before console login
through a dedicated `AuthorizedKeysFile`, while CI fetches the private key
ephemerally from Vault.

HotM's native workflows now:

- verify the pinned Mutsu ED25519 host-key fingerprint;
- disable password and keyboard-interactive authentication;
- serialize heavyweight Tauri builds with a shared host lock;
- recover a stale lock only when its recorded owner process is gone; and
- test lock contention, timeout, release, and stale-owner behavior in CI.

## Security

The UI lockfile resolves PostCSS `8.5.25`, removing the high-severity
source-map path traversal advisory affecting the previous `8.5.14` lock.
The UI high-severity dependency audit is now blocking.

## Claim boundary

Windows is the only deferred operating system and remains tracked by
[Fortemi #1096](https://git.integrolabs.net/Fortemi/fortemi/issues/1096).
This release does not establish universal portability, complete backup of all
product state, launched GUI or native-dialog coverage, or one common schema
across the AIWG static index, Knowledge Shard transfer, and live Fortemi
persistence planes. The suite-wide audit remains `NO-GO`.
