# HotM 2026.6.0

**Release date:** 2026-06-02
**Type:** Installer and desktop capture reliability release.

This release hardens the Linux desktop install path and fixes the desktop video attachment pipeline. A fresh Linux install now brings up the local services needed for default HotM media processing, including Speaches/Whisper for audio/video transcription.

## Install

### Linux (one command)

```bash
curl -fsSL https://raw.githubusercontent.com/Fortemi/HotM/main/scripts/install.sh | bash
```

### Linux (.deb direct)

```bash
sudo apt-get install ./HotM_2026.6.0_amd64.deb
```

### macOS

```bash
hdiutil attach HotM_2026.6.0_aarch64.dmg
cp -R "/Volumes/HotM/HotM.app" /Applications/
hdiutil detach "/Volumes/HotM"
xattr -cr /Applications/HotM.app
```

### Docker UI image

```bash
docker pull ghcr.io/fortemi/hotm-ui:2026.6.0
```

## What changed

### Linux install provisions transcription by default

The bootstrap installer now installs Docker when needed and starts a local Speaches/Whisper service as `hotm-speaches` on `127.0.0.1:8000`. The default desktop profile enables transcription jobs and passes `WHISPER_BASE_URL` to the bundled Fortemi sidecar.

Operators can disable or customize that component:

```bash
./scripts/install.sh --no-whisper
./scripts/install.sh --whisper-model Systran/faster-distil-whisper-large-v3
./scripts/install.sh --whisper-image ghcr.io/speaches-ai/speaches:latest-cpu
```

When `--no-whisper` is used, the installer writes `components.whisper=false` so the sidecar does not schedule local transcription work for a service that is intentionally absent.

### Desktop video upload reliability

Desktop capture now routes local file attachments through the native Tauri host adapter and the desktop upload/TUS path. This fixes the failure mode where committing a capture note scheduled jobs but did not transfer the selected video file.

Upload progress is emitted to the UI, and the sidecar limit for local desktop uploads has been raised for large media files.

### Installer cleanup

The Linux installer now behaves more consistently on fresh or reset hosts:

- `--local-deb` paths are canonicalized before privilege changes.
- PGDG key recovery is retried cleanly when apt key state is stale.
- Config and log paths resolve to the operator's home directory during sudo-driven installs.
- Local-mode launcher config controls whether Ollama and Whisper endpoints are passed to the sidecar.

### Job event cleanup

Retrying a queued job now removes stale completed or failed event entries when the same job is queued or started again. This keeps the job panel from showing old failed cards after a retry is already in progress.

### Dependency audit

The transitive dev dependency `ws` was updated from `8.19.0` to `8.21.0`, clearing the moderate npm audit advisory present during release prep.

## Compatibility

No breaking changes to existing HotM data or UI workflows.

Linux hosts that should not run local Docker-backed transcription should install with `--no-whisper`. Existing installs can rerun the installer; HotM preserves user data and updates the desktop component config idempotently.
