# API Compatibility Report

## Summary

The current change is an additive compatibility correction to `docs/openapi.json`. It documents behavior already used by the HotM UI client and covered by existing API unit tests.

## Classification

| Change | Type | Compatibility |
| --- | --- | --- |
| API server default updated to `http://localhost:3000/api/v1` | Documentation correction | Non-breaking for runtime; consumers should prefer the current Fortemi sidecar port. |
| Added optional `CreateNoteRequest.title` | Optional request field | Non-breaking. |
| Added optional note revision, document type, context filter, and processing controls | Optional request fields | Non-breaking. |
| Added `CreateNoteResponse.id` and `note_id`, retained legacy `noteId` | Optional response aliases | Non-breaking. |
| Added `POST /notes/reprocess` | New endpoint | Non-breaking. |
| Added `POST /backup/import` with optional `defer_inference` | New endpoint/optional field | Non-breaking. |
| Added `/webhooks` lifecycle, `/webhooks/{id}/deliveries`, and `/webhooks/{id}/test` | New endpoints/schemas | Non-breaking; documents endpoints already used by `ui/src/api/webhooks.ts`. |

## Consumer Impact

- HotM UI: positive impact; the spec now reflects fields already sent by `ui/src/api/notes.ts`, `ui/src/api/backup.ts`, and `ui/src/api/webhooks.ts`.
- Generated clients: positive impact; clients can expose newer controls without hand-maintained overrides.
- Legacy consumers: no removal of documented aliases in this correction.

## Follow-Up Controls

1. Maintain the lightweight spec-presence test for schemas and endpoints used by the UI client: `ui/src/api/__tests__/openapi-contract.test.ts`.
2. Establish an upstream Fortemi contract baseline when a canonical spec is available.
3. Run OpenAPI diff tooling before any future endpoint removal, required-field addition, enum contraction, or type change.
